ML Engineering · AXA · 2025

Prédiction du churn à l'échelle sur Databricks

Passer de données clients massives à des scores de risque intégrables dans les applications CRM, avec une chaîne ML testée et déployable.

RôleConsultant Data Scientist
Volume≈ 5 millions de lignes
StackPySpark · CatBoost
Résultat+18 % de précision

Le problème

Détecter plus tôt les clients à risque.

Les équipes de rétention avaient besoin d'un ciblage plus précis pour concentrer leurs actions sur les clients présentant un risque réel de résiliation. Le volume imposait une préparation distribuée et une chaîne reproductible, au-delà d'un modèle exploratoire.

Contribution

Industrialiser tout le cycle ML.

Databricks
02 · FeaturesPySpark
Contrôles qualité

CatBoost

Applications CRM
  • Exploration et transformation distribuée des données avec PySpark.
  • Feature engineering orienté comportement client.
  • Entraînement et comparaison de modèles XGBoost et CatBoost avec validation croisée.
  • Structuration du code en packages Python testés unitairement.
  • Automatisation des déploiements via Azure Pipelines.
  • Déploiement avec Databricks Model Serving pour l'intégration CRM.

Principes

Optimiser pour la décision, pas pour une métrique isolée.

Validation robuste

La comparaison des modèles s'appuie sur une validation croisée afin de limiter les conclusions liées à un découpage favorable.

Chaîne reproductible

Le code packagé et testé réduit les écarts entre expérimentation et déploiement.

Sortie actionnable

Le serving n'est pas une fin : les prédictions sont conçues pour rejoindre le workflow CRM et soutenir les campagnes de rétention.

Résultat

+18 % de précision sur les clients à risque.

Le résultat publié dans le CV correspond à une amélioration de la précision de détection des clients à risque. Les détails du benchmark, les données et les paramètres restent confidentiels.

Qualité de production

Ce qui rend le système exploitable.

  • Transformations distribuées adaptées au volume.
  • Validation et comparaison explicites des modèles.
  • Tests unitaires sur les packages Python.
  • Déploiement reproductible par CI/CD.
  • Interface de serving prévue pour les consommateurs métier.
